# 模型能讀整本書了，還需要 RAG 嗎？

## 這是什麼？為什麼重要？
**上下文視窗（context window）**是模型一次能讀進的內容上限。早期的語言模型，訓練時一次只讀 512 到 2,048 個 token [[sources/liu2023]] (§1)，所以必須靠 RAG 先挑出重點。現在的模型越讀越多：
- gao2024 撰寫時（2024 年初），已經有模型可以處理超過 20 萬個 token [[sources/gao2024]] (§VII-A)。
- Gemini-1.5-Pro 可以讀 100 萬個 token [[sources/li2024]] (§1, §3.2)。

這引發一個問題：如果整份文件都能直接丟給模型讀，還需要 RAG 嗎？這種直接讀全文的做法，稱為**長上下文（Long-Context，LC）**[[sources/li2024]] (§1)。

💡類比：RAG 像考前請助教幫你畫重點，只讀重點段落；長上下文像自己把整本書從頭讀到尾。讀整本可能比較完整，但非常花時間。

## 實驗結果：LC 成績較好，RAG 便宜很多
[[sources/li2024]] 用三個 2024 年的模型比較：
- 資源充足時，LC 的平均成績贏過 RAG：Gemini-1.5-Pro 多 7.6%，GPT-4O 多 13.1%，GPT-3.5-Turbo 多 3.6% [[sources/li2024]] (§3.3)。
- 但文件遠超過模型上限時，RAG 反而比較好 [[sources/li2024]] (§3.3)。
- RAG 的輸入短很多，成本也低很多，因為模型服務通常依輸入的 token 數計費 [[sources/li2024]] (§1)。
- 兩種方法對 63% 的問題給出完全相同的答案 [[sources/li2024]] (§4.1)。

## 兩全其美：Self-Route
[[sources/li2024]] (§4.2) 提出 **Self-Route（自我路由）**：
1. 先用 RAG 找出的片段請模型回答，並允許它說「資料不夠，無法回答」。
2. 只有說「無法回答」的問題，才把整份文件交給它讀。

結果成績接近 LC，成本卻大幅下降：Gemini-1.5-Pro 減少 65%，GPT-4O 減少 39% [[sources/li2024]] (§1)。

💡類比：就像看病的分級轉診。小感冒在社區診所處理就好（RAG），診所處理不了的才轉到大醫院做全身檢查（LC）。大部分人不必排大醫院，整體省時又省錢。

## RAG 仍有的優勢
[[sources/gao2024]] (§VII-A) 認為 RAG 仍不可取代：
- **速度**：一次塞大量內容會拖慢模型，按需檢索比較有效率。
- **可追溯**：RAG 可以指出答案根據哪幾段資料，方便查證；只靠長上下文則像黑盒子。

### ⚠️ 觀點分歧：長上下文會取代 RAG 嗎？
- [[sources/li2024]] (§3.3)：新一代模型資源充足時，LC 的成績一致贏過 RAG。
- [[sources/liu2023]] (§2.3)：能讀更長內容的模型，並沒有比較會使用中間的資訊；讀得長不代表讀得好。
- [[sources/gao2024]] (§VII-A)：RAG 在速度和可追溯性上仍不可取代。
- li2024 自己也指出，更早的研究（Xu et al., 2023）得到相反結論，認為長上下文落後 RAG [[sources/li2024]] (§2)。
- **為什麼不同**：年代和模型不同。liu2023 測的是 2023 年的模型，li2024 測的是 2024 年更強的 Gemini-1.5-Pro 和 GPT-4O，li2024 也把差異歸因於「更強的模型、更長的文件」[[sources/li2024]] (§2)。另外，gao2024 談的是成本與透明度，li2024 談的主要是答對率，兩者比較的重點不同。
